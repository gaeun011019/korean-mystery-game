# 개발 안내

정답과 사건 논리를 검토하려면 `src/*cases.js`와 `src/case-data.js`를 읽으세요. 이 파일들은 스포일러를 포함합니다. 웹 실행에는 Node 기본 모듈만 사용하며 외부 패키지·API·서버 데이터베이스가 없습니다.

## 사건 자료와 저장 호환성

각 사건은 고유 `id`, `revision`, 인물·장소·단서·질문·힌트·제출 근거·해설을 가집니다. `src/case-data.js`의 `cases` 배열이 사건 선택 화면을 구성합니다.

진행 저장 키는 `case-notebook:save:<caseId>`입니다. 저장 스키마 버전·사건 ID·revision과 진행의 유효성을 확인합니다. 기존 사건의 ID, 단서·질문 ID, 필수 조건이나 revision을 바꾸면 저장 호환성에 영향을 줄 수 있습니다. 단순한 예상 시간·소개 문구 조정에는 저장 스키마를 바꿀 필요가 없습니다.

새 사건은 새 ID로 추가하세요. 기존 기록을 자동으로 삭제하거나 새 사건의 키에 덮어쓰지 마세요. 손상·버전 불일치 기록을 보존하고 사용자가 확인한 해당 사건의 초기화만 허용합니다. 현재 저장은 한 브라우저 origin에 한정되며 동기화·다중 탭 병합 기능은 없습니다.

## 개발 서버와 빌드 미리보기

`node dev.mjs`와 `node dev.mjs preview`는 모두 `http://127.0.0.1:4173/`만 사용합니다. `PORT` 환경변수는 무시하며 포트 충돌 시 오류를 안내하고 종료합니다. 기존 서버가 이 프로젝트의 서버이면 재사용하고, 개발/빌드 미리보기 간 전환 시 이 프로젝트의 서버만 종료하세요. 다른 앱의 프로세스를 임의로 종료하지 마세요.

## 검사

- `game.test.js`: 첫 사건의 규칙과 720개 단서 순서·108개 제출 조합 회귀.
- `cases-save.test.js`: 기존 세 사건 및 저장 검증·실패·복원.
- `expanded-cases.test.js`: 새 사건의 증거 조건, 384개 조사 경로·256개 제출 조합, 선택적 대화·힌트·기존 저장 원문 보존.
- `ui.test.js`: 실제 앱 모듈을 최소 DOM 어댑터로 실행해 다섯 사건 선택·조사·제출·재로드·독립 초기화를 검사. 브라우저 렌더링 검사는 아님.

`node --test tests/*.test.js` 또는 `npm test`로 실행합니다. Windows PowerShell에서는 `npm.cmd test`도 사용할 수 있습니다.

## 저장 오류의 수동 브라우저 확인

일반 서버는 테스트 파일을 제공하지 않습니다. 오류 확인 전용 서버는 아래 명령으로 실행합니다.

```bash
node tests/browser-server.mjs
```

`http://127.0.0.1:44974/tests/browser-fixture.html`에서 저장 차단·복구, 손상 JSON, 이전 버전 기록을 재현할 수 있습니다. **이 버튼은 해당 브라우저의 해당 origin에 테스트 기록을 만들거나 교체합니다.** 새 시크릿 창이나 별도 테스트 프로필을 사용하고 그 주소에서 진행한 사용자 기록이 없는지 확인하세요. 일반 플레이 주소와 혼동하지 마세요.

확인 항목은 실패 안내·진행 유지·재시도 복구, 초기화 취소 후 손상 기록 보존, 확인한 사건만 초기화되는지입니다. 실제 사용자 저장을 테스트용으로 지우지 마세요.

## 빌드와 검증 한계

`node dev.mjs build`는 실행에 필요한 HTML·CSS·JS 8개를 `dist/`로 복사합니다. 서버의 허용 파일 목록은 `dev.mjs`에 있으며 테스트·기획 문서·설정 파일을 제공하지 않습니다. 새 소스 모듈을 추가하면 빌드와 서버 허용 목록을 함께 갱신하세요.

현재 검사 결과와 지원 환경은 README를 확인하세요. 새로운 사건·UI·저장 규칙을 바꾸면 자동 검사와 별도 브라우저 프로필에서의 실제 플레이를 모두 검토하세요. 예상 플레이 시간은 사람의 읽기·추론 경험에 대한 기획 추정이며 자동 검사 실행 시간과 다릅니다.
